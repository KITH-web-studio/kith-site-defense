# Уведомления и контроль работы

[Документация](README.md)

## Email, Telegram и webhook

Откройте **Site Defense → Уведомления** и настройте нужные каналы.

| Канал | Что указать |
| --- | --- |
| Email | Включите отправку, укажите адрес и отметьте типы событий. Плагин использует `wp_mail()` WordPress. |
| Telegram | Создайте бота через BotFather. Укажите его токен и ID чата. Для личного чата сначала отправьте сообщение боту, для группы добавьте бота в группу и дайте ему право отправлять сообщения. |
| Webhook | Укажите публичный HTTPS-адрес приёмника и общий секрет для проверки подписи. |

Сохраните параметры и нажмите **Отправить тестовое уведомление**. Убедитесь, что сообщение получено. Для уведомлений об уязвимостях выберите соответствующий тип события в email. Telegram получает такие уведомления вместе с другими инцидентами. Уведомления об уязвимостях через webhook исключены.

Токен Telegram и секрет webhook хранятся в зашифрованном виде. После смены солей WordPress сохраните эти секреты заново. Уведомления содержат сведения о событии и ссылки на сайт и карточку инцидента.

## Если уведомления не приходят

1. Проверьте, включён ли канал и получает ли он тестовое уведомление.
2. В той же вкладке проверьте время последнего запуска доставки. Очередь обрабатывается каждую минуту через WP-Cron. Низкий трафик, недоступный приёмник и объём очереди могут задерживать доставку.
3. Запустите обработку вручную и снова проверьте результат.

```sh
wp site-defense notifications status
wp site-defense notifications test
wp site-defense notifications deliver
```

Попытки, заблокированные за пять минут, могут объединяться в одно оповещение. При сбоях доставки плагин повторяет отправку с увеличением интервала, до часа. Для регулярных запусков настройте [системный cron](wp-cli.md#запуск-по-расписанию).

### Проверка подписи webhook

Приёмник берёт исходное тело запроса и заголовок `X-Site-Defense-Time`. Вычислите HMAC-SHA256 от строки `timestamp + "." + raw_body` с общим секретом и сравните результат с `X-Site-Defense-Signature`. Проверяйте свежесть времени и учитывайте повторную отправку одного сочетания `id` и `occurrences`.

## Независимый контроль

Внешний контроль помогает заметить, что сайт перестал отправлять сигнал или зависли задачи доставки или проверки файлов. Для каждого сайта запустите [приёмник](../tools/heartbeat-monitor.py) на отдельном сервере и используйте отдельный файл SQLite.

1. Передайте в окружение приёмника `SD_HEARTBEAT_SECRET` со случайным секретом из 32–128 URL-безопасных символов. Храните SQLite вне публичного каталога.
2. Запустите приёмник и направьте запросы HTTPS к `/heartbeat` на этот процесс.
3. В WordPress откройте **Site Defense → Уведомления → Внешний контроль работы**. Укажите HTTPS-адрес приёмника и тот же секрет, сохраните параметры и нажмите **Отправить сигнал сейчас**.
4. Запускайте `check` каждую минуту планировщиком отдельного сервера. Для Telegram задайте `SD_MONITOR_TELEGRAM_TOKEN` и `SD_MONITOR_TELEGRAM_CHAT`. Метку сайта можно задать через `SD_MONITOR_SITE_LABEL`.

```sh
python3 tools/heartbeat-monitor.py --state /var/lib/site-defense/store.sqlite serve --bind 127.0.0.1 --port 8787
python3 tools/heartbeat-monitor.py --state /var/lib/site-defense/store.sqlite status
python3 tools/heartbeat-monitor.py --state /var/lib/site-defense/store.sqlite check --timeout 900
```

Приёмник проверяет HMAC-SHA256, время и повторную отправку. Внешний монитор оповещает о пропадании сигнала, зависании фоновых задач и восстановлении работы.
