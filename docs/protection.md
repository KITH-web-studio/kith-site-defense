## Настройки по умолчанию

| Включены при установке | Включаются по необходимости |
| --- | --- |
| Ограничение попыток входа, WAF и проверка изменений ключевых файлов. Ежедневная сверка известных уязвимостей и получение CISA KEV запланированы через WP-Cron. | Защита профилей через REST, ограничения XML-RPC, запрет редактора PHP, обязательная 2FA, отдельный адрес входа, ранний WAF, ежедневное полное сканирование, WPVulnerability и доставка оповещений. |

В комплекте есть снимок базы Wordfence Intelligence. Фоновая загрузка новой базы требует адреса издателя. По умолчанию в сборке этот адрес пуст, поэтому локальные данные доступны сразу, а поставку свежих пакетов настраивает владелец сайта.

## Вход и аккаунты

Откройте **Site Defense → Вход**. Ограничение попыток учитывает пару «IP и учётная запись» и общую частоту с IP. При временной блокировке браузер получает HTTP 429. В этой же вкладке можно сбросить ограничения.

- **Отдельный адрес входа.** Введите новый путь и нажмите **Проверить новый адрес**. Откройте тестовый адрес в приватном окне и войдите под тем же администратором в течение 15 минут. После успешной проверки Site Defense активирует адрес. На случай потери доступа оставьте себе доступ к хостингу или WP-CLI.
- **2FA для своей учётной записи.** Откройте настройку аутентификатора, подтвердите код и сразу сохраните одноразовые коды восстановления. Для настройки нужны HTTPS и Sodium.
- **Обязательная 2FA.** Включается отдельным переключателем для привилегированных аккаунтов. При следующем входе пользователи без второго фактора проходят настройку после проверки пароля. Существующие сессии таких аккаунтов теряют привилегированный доступ. Для аварийного снятия политики используйте `wp site-defense policy disable --yes`.
- **REST и XML-RPC.** Если внешним приложениям нужны профили авторов через REST или вход по XML-RPC, проверьте эти сценарии перед включением ограничений. Pingback отключается отдельно.

В разделе **Защита** указывайте IP доверенного обратного прокси только при условии, что он перезаписывает `X-Real-IP` для каждого запроса. Site Defense использует это значение для определения IP клиента, когда соединение пришло от указанного прокси.

## Правила WAF

Во вкладке **WAF** видны адресные правила, применимость к установленной версии и режим. **Наблюдение** регистрирует совпадения и пропускает запрос. **Блокировка** возвращает HTTP 403. **Выключено** приостанавливает правило.

Встроенные адресные правила нацелены на конкретные компоненты и диапазоны версий. Сборка включает защиту от обхода пути в затронутых версиях ядра и правила наблюдения для WooPayments и Canto. Ссылки на бюллетени перечислены в [документации выпуска пакетов](releases.md#подписанные-пакеты-правил).

Перед переводом правила в блокировку проверьте журнал и обычные сценарии сайта. Для WooCommerce проверьте вход, оформление заказа и колбэк оплаты. При ошибочном срабатывании верните правило в режим наблюдения и сохраните ID совпадения для разбора. Журнал фиксирует правило и маршрут, значения параметров, тела запроса и cookies исключены из записей WAF.

В той же вкладке можно импортировать подписанный пакет и откатиться к предыдущему. Откат сохраняет выбранные режимы правил по ID. Повторный импорт уже использованной или более старой версии отклоняется.

### Ранняя защита

Обычные правила WAF выполняются при загрузке WordPress. Для проверки прямых запросов к PHP-обработчикам настройте **Раннюю защиту** во вкладке **WAF**.

1. Проверьте, использует ли хостинг свой `auto_prepend_file`. Если использует, согласуйте настройку цепочки загрузки с хостингом.
2. Включите раннюю защиту. Site Defense добавит управляемую запись в `.user.ini`, загрузчик `sd-prepend.php` и правило для каталога загрузок на Apache 2.4. На Nginx примените подсказку из интерфейса в конфигурации сайта перед общим обработчиком PHP.
3. После истечения кеша `user_ini.cache_ttl` нажмите **Проверить раннюю защиту**. Проверьте обычный вход и работу сайта.

При деактивации плагин выключает управляемую конфигурацию и сохраняет загрузчик для PHP-процессов с ещё действующим кешем. Хронология получает ранние события после обработки буфера задачей доставки. [Сопоставление событий с журналом прокси](mcp.md#журнал-обратного-прокси)

## Источники уязвимостей

| Источник | Как используется |
| --- | --- |
| Wordfence Intelligence | Снимок уже включён в ZIP, версии ядра, плагинов и тем сверяются локально. Для обновления импортируйте более новый подписанный пакет в Site Defense или задайте адрес издателя. |
| WPVulnerability | Включается во вкладке **Уязвимости**. Плагин запрашивает сведения по идентификаторам установленных компонентов через публичный HTTPS API, кеширует ответы и сверяет версии локально. При сбое сохраняется последний успешный результат. |
| CISA KEV | Выделяет CVE, по которым известно об эксплуатации. Каталог обновляется ежедневно при работающем WP-Cron. При сбое используется предыдущая копия. |

Из вкладки **Уязвимости** можно поставить сверку в очередь, импортировать подписанный пакет и запросить обновление CISA KEV. Ручной импорт также доступен через `wp site-defense database import /secure/database.pack`.

Оповещения отправляются о новых находках. Совпадения разных источников для той же уязвимости компонента объединяются. Для уже известной CVE добавление в KEV может вызвать отдельное оповещение о повышении приоритета. Сверка версий помогает расставить приоритеты. Установка исправленной версии компонента остаётся отдельным действием.
